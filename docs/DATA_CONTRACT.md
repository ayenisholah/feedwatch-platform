# Data contract

**Updated:** 2026-11-18

The repos share data in two places. Each has one machine-readable source of truth, and its consumers pin a released version of it.

| Contract              | Producer           | Consumers                | Source of truth                                                                                               |
| --------------------- | ------------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| InfluxDB measurements | `feedwatch-poller` | `feedwatch-api`, Grafana | [`contracts/influx-schema.json`](../contracts/influx-schema.json) in this repo, released by tag `contract-vN` |
| HTTP API              | `feedwatch-api`    | `feedwatch-web`          | `openapi.json`, generated by the API with utoipa and attached to each API release                             |

Changing a contract means: bump its version, release it, then update each consumer in its own pull request. Consumers run a contract test that fails on a mismatch.

## InfluxDB

Bucket `feedwatch`, organisation `feedwatch`. Current version: **2** (v2 made `deviation_threshold_pct` optional, because cron-scheduled feeds have no deviation trigger). Timestamps are in seconds and UTC. Values are stored as floats, already scaled by the feed's `decimals`; the raw integer answer is kept as a string, so no precision is lost.

| Measurement  | Tags                                                                              | Fields                                                                                                                                                                      | Written              |
| ------------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `feed_round` | `chain`, `feed_id`                                                                | `value` (float), `answer_raw` (string), `round_id` (string), `updated_at` (int, unix s), `age_s` (int)                                                                      | Every poll, per feed |
| `feed_check` | `chain`, `feed_id`, `status` (`ok`, `stale`, `drift`, `error`)                    | `heartbeat_s` (int), `deviation_threshold_pct` (float, absent for cron-scheduled feeds), `reference_deviation_pct` (float, optional), `reference_source` (string, optional) | Every poll, per feed |
| `rpc_call`   | `chain`, `provider`                                                               | `latency_ms` (int), `ok` (bool), `calls` (int)                                                                                                                              | Every batch          |
| `incident`   | `chain`, `feed_id`, `kind` (`stale`, `drift`, `error`), `event` (`open`, `close`) | `incident_id` (string), `detail` (string)                                                                                                                                   | When status changes  |
| `poll_cycle` | none                                                                              | `duration_ms` (int), `feeds` (int), `failed_feeds` (int)                                                                                                                    | Every poll           |

Retention: 30 days on the bucket. Chains are `ethereum`, `arbitrum` and `base`. `feed_id` is the manifest key exactly as written, for example `ETH` or `pzETH_FUNDAMENTAL`.

## API

Mounted under `/api`, read-only and JSON. Current version: **[v0.1.0](https://github.com/ayenisholah/feedwatch-api/releases/tag/v0.1.0)**. Its `openapi.json` (OpenAPI 3.1, generated by utoipa) is the authoritative schema, attached to each feedwatch-api release and also served live at `/api/openapi.json`. feedwatch-web pins a released version.

| Route                                 | Returns                                                                                                                                                   |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/health`                     | `{ status: "ok" \| "degraded", influx: "ok" \| "down", lastPollAt }`, always 200, within 1 s                                                              |
| `GET /api/feeds?chain=`               | `{ lastPollAt, feeds }`: each feed's latest round and check (round fields `null` if it couldn't be read), by chain then feed ID; 400 for an unknown chain |
| `GET /api/feeds/{chain}/{feedId}`     | `{ latest, series }`: the latest round and check, and 24 h of `{ t, value, ageS }` in 5-minute windows; 404 with no data in 24 h                          |
| `GET /api/compare`                    | `{ lastPollAt, feeds }`: the feeds on all three chains, each with `chains.{ethereum,arbitrum,base}` and `spreadPct`                                       |
| `GET /api/incidents?status=open\|all` | `{ incidents }`: `{ id, chain, feedId, kind, openedAt, closedAt, detail }`, newest first, at most 500, from the last 30 days                              |
| `GET /api/openapi.json`               | The OpenAPI document                                                                                                                                      |

Errors are `{ error }` with 400, 404, 429 or 503. Limits (GR-2): GET only, CORS for the site origin only, 20 requests per client at once refilled at 2 per second, and data routes cached for 30 s (`Cache-Control: public, max-age=30`).
